# 按需智囊团

这是由当前 Agent 执行的协作协议。它不启动后台进程，也不创建常驻人物 Agent。
个人成员名单、影响经历和来源目录只保存在绑定 Vault 的 Myself 项目中。

## 与人生方向流程的顺序

首次设置可以先询问用户想参考的作者、访谈者、实践者或方法，以及“为什么希望听取这个视角”，只保存候选名单和来源缺口。完整配置与调用通常放在当前状态、人生罗盘和三条奥德赛草案之后。

这个顺序让智囊团检查已经出现的路线、代价和隐藏假设，避免用户在表达自己的价值和可能生活之前，先被崇拜对象的语言替代。用户已经面临具体决定时可以提前调用，但必须先写明本人的目标、约束和现有选项。

## 入口与路由

用户要求智囊团分析、比较思想视角或讨论受某作品影响的决定时：

1. 读取 Vault 的 `07 项目/Myself/智囊团.md`（若存在）及本次相关材料。明确问题、可选方案、本人目标、约束、期限和未知信息；不要默认其喜爱的作者代表其所有价值观。
2. 简单问题选一个相关视角，由主 Agent 回答。复杂或重要问题选 2–3 个互补视角；有可用多 Agent 工具且已获授权时，委派只读独立分析。没有该能力时明确说明是同一 Agent 的多视角分析，不称为独立验证。
3. 每个 Worker 收到同一份最小背景、相关来源、任务和输出约定；首次分析不提供其他 Worker 的结论。不得修改 Vault 或读取无关私人资料。
4. 涉及判断的综合结论交给独立 Verifier。复核证据与反例后至多进行一轮针对性修正；尚不能解决的分歧保留。
5. 主 Agent 解释共识、分歧、关键未知和可逆下一步。用户作出个人取舍；按现有写入协议沉淀有价值的结果。

来源不足时缩小结论，先回答有依据的部分；不要为了凑齐角色而编造作者观点。

## 角色与输出

- **主协调 Agent**：理解问题、选择视角、控制范围、综合并核对已有授权。
- **思想或方法视角**：可以对应作者、一本书或一个方法，不扮演作者本人，不声称还原其未公开的思考。
- **证据与反例 Verifier**：检查原文归属、时间、适用条件、证据缺口、相反解释和是否超出用户授权。
- **单一 Writer**：仅写入已授权范围，复用知识系统的预览、版本检查、恢复点和验证。

各视角使用同一输出约定：

1. 观点与原始出处；标明核实程度、版本或日期。
2. 本人已经陈述的事实，以及本次分析新增的推断。
3. 支持依据、反例、适用前提和代价。
4. 替代解释或替代行动。
5. 一项可验证的行动：观察指标、复查时点，以及什么结果会使建议改变。

提供简洁、可审查的理由，不把文风模仿当成理解。

## 证据与影响关系

分别记录：作者原话或作品主张、本人对其影响的陈述、AI 的应用推断、实践结果。
某作者引用另一作者时，保留“引用/转述”关系和具体出处；只有用户回忆而无原文时标为待核实。
多个角色使用同一来源不算多份独立证据，不按票数形成结论。
个人经验、实践方法、科学研究结论和营销案例不能互相替代。

成员名单表示当前愿意参考的视角，不是永久认可全部观点。作者观点变化时按日期保留差异。

## 写回与效果验证

依据 [知识系统](knowledge-system.md) 和 [Agent 协作协议](agent-protocol.md) 操作。
检索先定位页面，再核对原始来源；AI 摘要不能循环引用成为新证据。
个人正式决定不由知识页自动覆盖；记录采用和未采用的建议、理由与后续结果。
角色配置或调用规则的改进先作为试用方案，实际效果未知时明确保留未知。
评估是否找到可追溯依据、发现一个有用反例、产生可执行下一步，以及后续结果是否支持建议。
不要以 Agent 赞同率衡量正确性，也不要宣称尚未接入的向量检索或自动自迭代已经生效。
