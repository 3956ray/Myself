# Agent 协作协议

## 兼容范围

生成后的 vault 只依赖本地 Markdown 与 Python 标准库。任何能够读取目录、编辑文件和运行命令的 Agent 都可以协作。`AGENTS.md` 是通用入口；若工具不自动读取它，请在首条消息中要求读取。

## 推荐启动提示词

```text
请先完整阅读 AGENTS.md，并按其中的 read order 读取系统规则。
我的 vault 是唯一正式状态源；聊天内容只是候选输入。
先说明本次 Goal、排除范围、as_of、time_scope、证据缺口和隐私等级。
没有我的明确批准，不要更新正式状态、战略或决策页面。
如果本次涉及人生方向，请核对 99 系统/奥德赛方法与来源.md；
同时阅读 99 系统/适用对象与成果.md；
不要根据分数替我选择奥德赛路线。
```

## 输入契约

每次重要运行应明确：

- Goal 与不在范围内的内容；
- `as_of` 与 `time_scope`；
- 输入页面及版本；
- Evidence 与仍缺失的信息；
- `sensitivity`；
- 成功、失败和停止条件；
- 是否允许提出文件变更。

当前与未来混合、关键输入缺失或敏感内容未脱敏时，Agent 应停止并报告，而不是补全故事。

## 输出契约

正式输出至少包含：

1. 事实、感受、解释、假设和决定的分离结果；
2. 支持与反对证据及其时间范围；
3. 冲突、缺失、替代解释和隐私风险；
4. 最多三个下一步行动及成功／失败条件；
5. 需要修改的具体页面与字段；
6. Verifier 状态和本人需要批准的范围。

涉及奥德赛时还需列出：三个计划是否真正不同、跨计划共同元素、待验证的关键未知、原型成本边界，以及哪些判断必须留给本人。

面对尚无正式工作经历的用户，课程、社团、项目、兼职、实习、志愿服务和家庭责任都是有效观察来源。Agent 应通过问题引导用户形成方向，而不是根据学历、排名、薪资或社会期待给出专业／职位结论。

## 多 Agent 调用

只有同时满足以下条件才使用 Worker：

- 至少两个子任务边界清楚且彼此独立；
- 输入可以冻结到同一 `as_of` 和页面版本；
- 每个 Worker 只读；
- Root 知道预期返回数量并能确定性合并；
- 敏感内容已经最小化。

Verifier 应获得新上下文，只接收待验证 Claim、对应 Evidence、时间范围与验收条件。不要把分析者整段对话交给 Verifier。

## 文件写入协议

涉及当前状态、战略、财务或重要决定时：

1. 建立证据或引用来源；
2. 使用变更提案模板列出实际差异；
3. 运行只读校验器；
4. 对判断性 Claim 进行独立验证；
5. 本人批准确切文件和范围；
6. 创建可恢复 Checkpoint；
7. 单一 Writer 写入；
8. 再次校验；
9. 追加变更和运行记录；
10. 设置结果复查日期。

## 不同 Agent 的接入方式

- **Codex / Claude Code / Cursor**：在 vault 根目录启动，要求读取 `AGENTS.md`。
- **Chat 型 Agent**：只上传本次需要的最小页面；先让它输出候选提案，再由本地 Agent 执行受控写入。
- **无文件写入能力的 Agent**：作为只读 Worker 或 Verifier 使用，不作为 Writer。
- **自动化系统**：只能写入收件箱或追加式日志；不得直接覆盖罗盘、状态或战略。
