# 跟着完成一次真实选择

以下人物、日期、预算和观察全部虚构，仅演示填写与思考方式，不是推荐的人生方案。

## 场景：是否把业余时间投入一个新方向

虚构用户小林希望尝试翻译，但还不知道是否喜欢实际工作。先完成一次小实验，不要求先填满所有年度与三年页面。

### 1. 整理上下文

在收件箱写入候选：

| 类别 | 虚构示例 |
|---|---|
| 事实 | 本人记录显示，下周可支配时间约四小时 |
| 感受 | 对翻译感到好奇，也担心占用休息 |
| 解释 | 可能喜欢语言工作；尚非能力结论 |
| 假设 | 做一份小样并接受反馈，可以减少对实际工作的未知 |
| 待决定 | 是否批准一个两周、总计不超过八小时的试验 |

交给 Agent：

> 只读取本次相关页面。帮我找出已知、未知和替代解释，比较维持现状、延后和小实验三个选项，提出最多三个行动。尚未批准的内容保留为候选。

### 2. 把选择缩小成可观察的实验

用实验记录模板创建候选，填写：

- `scope_start: 2030-09-23`、`scope_end: 2030-10-06`、`review_due: 2030-09-30`。
- 行动：完成一份有权使用的短文翻译，征得一位愿意试读的人的反馈。
- 成功信号：完成小样、获得具体反馈，并能说明愿不愿再做一次。
- 停止条件：超过时间上限或明显挤占休息。
- 未知：是否存在持续需求、是否愿意付费；本轮不作收入结论。

这是跨季度实验。当前季度仍保留 Q3，跨到十月不等于已经批准 Q4 计划。若需要改变原来的时间安排，使用阶段重规划模板，明确从哪里调配八小时。

### 3. 批准与执行分开

Agent 展示具体文件差异、依据与验收。完成验证、本人批准和 Checkpoint 后，保存正式安排及日志。实验仍可为 `proposed`。

假设九月二十四日实际完成第一段翻译，再记录行动、证据，填写 `started_on: 2030-09-24`、更新 `as_of`，并转为 `active`。未来打算不算执行记录。

### 4. 到期复查

假设九月三十日小样完成，但试读者还没回复：

- 已知：产出了小样，实际用了三小时。
- 未知：对接收者是否有用。
- 判断：外部价值的证据不足，不能宣布需求成立或不存在。
- 下一步：在剩余预算内取得一次具体反馈，或到结束日停止并记录限制。

复查留在实验与周复盘中。只有得到相应证据并批准变更后，才调整正式状态或方向。

## 如何判断用户是否真正上手

观察对方能否自行完成“整理上下文 → 提出选择 → 得到可执行的下一步”，记录卡住的步骤。另一个场景再次使用可作为后续价值信号；框架写完、点赞或自己的满意不等于真实使用，更不等于付费验证。
