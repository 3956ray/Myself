# 0.2 框架改进与迁移

## 本轮范围

从个人实例的使用方式提炼三个通用需求：现实变化后的有界计划、实验批准与启动分离、可跟随的上手案例。公开内容采用通用结构与虚构示例，不复制个人经历或私人来源链接。

## 新建 vault

正常运行初始化器即可获得阶段重规划指南和模板、实验执行与复查栏目、周复盘回流栏目，以及日期校验。

## 已有 vault

不要覆盖整个目录。先建立备份并按实例自己的写入协议处理明确差异：

1. 比较并添加 `99 系统/阶段重规划.md`、`90 模板/阶段重规划.md`，将 `__INIT_DATE__` 替换为本次迁移日期。
2. 合并首页、当前季度、工作流、实验和周复盘中的新增入口与栏目，保留已有内容、ID 与历史日期。
3. 合并数据契约和校验说明，再更新校验脚本。新增指南与模板暂未列入强制核心文件清单，以免仅更新校验器就要求旧实例补齐所有新页面。
4. 保留 `result_review_date` 兼容字段；推荐新记录采用 `review_due`，若同时使用两者需保持一致。不要猜测或重设实际复查日期。
5. 对已有实际启动证据再补 `started_on`；没有证据时留空。不要因旧记录标为 approved 就批量转成 active。
6. 运行校验，处理无效日期、反向区间或冲突字段。核对范围后记录迁移与结果。

日期校验不判断内容是否真实、批准是否有效或实验是否值得做；未填写的可选日期不会报错。完整性和判断仍需人工及相应验证流程。
