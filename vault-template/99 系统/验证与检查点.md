# 验证、Checkpoint 与结果复查

## 验证优先级

1. 真实结果、原始记录、账户或权威来源。
2. 确定性规则：Schema、链接、日期、计算、完整性和隐私。
3. 新上下文中的独立 Verifier。
4. 本人的价值判断与高风险批准。

同一 Agent 的自我检查可以补充，但不能替代外部证据或独立 Verifier。

## 确定性校验

重要写入前后运行：

```text
python3 "99 系统/scripts/validate_vault.py"
```

校验器只读检查核心页面、frontmatter、状态词汇、ID 唯一性、日期格式与起止顺序、复查日期别名一致性、实际启动与 as_of 的顺序、Wiki-link、敏感信息模式和复盘实例。Error 阻止写入；Warning 必须解释。

## 独立 Verifier

Verifier 只接收：待验证 Claim、对应 Evidence、时间范围、验收和失败条件。返回：`validated`、`rejected` 或 `insufficient_evidence`，并说明可复查原因。

## Checkpoint 协议

### 写入前

1. 明确变更提案、目标页面和排除范围。
2. 运行校验器并保存摘要。
3. 建立可恢复快照，例如 Git commit、带日期压缩包或可靠版本快照。
4. 在[[05 日志/工作流运行记录]]记录输入版本、批准和 Checkpoint。

### 写入时

1. 只有一个 Writer。
2. 只修改批准字段和页面。
3. 不移动或删除未经批准的历史证据。
4. 多页面按依赖顺序串行完成。

### 写入后

1. 再次运行校验器。
2. 对照提案检查实际差异。
3. 追加[[05 日志/变更日志]]和运行结果。
4. 设置现实结果复查日期。

## 回滚条件

- 校验出现 Error；
- 写入超过批准范围；
- 引入时间范围或跨页冲突；
- 关键证据丢失或无法追溯；
- 敏感信息进入不适当页面或上下文。

回滚后保留失败 Run 与原因，不把失败伪装成未发生。
